# Novaday 備份格式規格

這份規格說明 Novaday 的「完整備份」檔案格式。網頁版和 Flutter App 都要照這份規格讀寫，同一份備份才能在兩邊互相還原。

- 目前版本：**1**（第一個正式版本，之前沒有對外的備份格式，不需要相容舊格式）
- 網頁版實作：
  - 匯出：`src/js/features/backup/export.js` 的 `backupZip()`
  - 還原：`src/js/features/backup/restore.js` 的 `imLoadZip()`、`cleanEntry()`、`cleanProf()`
  - zip 讀寫：`src/js/core/zip.js`
  - 照片儲存（IndexedDB）：`src/js/core/photo-store.js`

## 1. 檔案

- 副檔名 `.zip`。檔名建議用 `Novaday-backup-YYYY-MM-DD.zip`，只用英文、數字和 `-`，因為部分瀏覽器和系統會把中文檔名換掉。
- zip 內容：

```
Novaday-backup-2026-10-02.zip
├── novaday-backup.json        紀錄、個人資料、回顧紀錄（必要）
├── photos/
│   ├── a1b2c3-1.jpg           紀錄 a1b2c3 的第 1 張照片（封面）
│   ├── a1b2c3-2.jpg           第 2 張
│   ├── vk3m9x2a-poster.jpg    影片 vk3m9x2a 的封面
│   └── avatar.jpg             照片頭像
└── videos/
    └── vk3m9x2a.mp4           影片檔
```

- 檔案的路徑一律以 JSON 裡記的為準。上面的命名只是匯出時的慣例，讀取時**不要**靠檔名推測。

### zip 的規則

| 項目 | 寫入時 | 讀取時 |
|---|---|---|
| 壓縮方式 | 不壓縮（stored，method 0）。照片和影片本身就是壓縮格式，再壓縮也小不了多少 | 要支援 stored（0）和 deflate（8）。使用者可能解壓縮後再重新壓縮 |
| 檔名編碼 | UTF-8（general purpose flag bit 11） | 以 UTF-8 解讀 |
| 大小上限 | 整份不超過 4 GB，不使用 ZIP64。超過時提示使用者先移除部分影片 | 遇到 ZIP64 可以回報「無法讀取」 |
| 多一層資料夾 | 不加 | 檔案可能被包在一層資料夾裡（例如 `Novaday-backup/novaday-backup.json`），要用路徑結尾比對 |
| 系統雜檔 | 不加 | 略過 `__MACOSX/`、`._*` 和資料夾項目 |
| 路徑安全 | 只寫 `photos/…`、`videos/…` | JSON 裡的路徑必須符合 `^(photos\|videos)/[A-Za-z0-9_.-]+$`，其他一律忽略，避免路徑穿越 |

## 2. `novaday-backup.json`

UTF-8 編碼的 JSON。

```json
{
  "app": "Novaday",
  "kind": "backup",
  "v": 1,
  "at": "2026-10-02T08:30:00.000Z",
  "platform": "web",
  "profile": { },
  "reviews": { "ids": { }, "last": null },
  "entries": [ ],
  "files": [ ]
}
```

| 欄位 | 型別 | 說明 |
|---|---|---|
| `app` | `"Novaday"` | 固定值 |
| `kind` | `"backup"` | 固定值 |
| `v` | 整數 | 格式版本，目前是 `1` |
| `at` | 字串 | 匯出時間，ISO 8601 UTC |
| `platform` | 字串 | 匯出的平台：`"web"`、`"ios"`、`"android"`，只是參考，讀取時不要依它改變行為 |
| `profile` | 物件 | 個人資料，見第 4 節 |
| `reviews` | 物件 | 回顧紀錄，見第 5 節 |
| `entries` | 陣列 | 日記紀錄，見第 3 節 |
| `files` | 陣列 | zip 裡所有照片和影片的清單，見第 6 節 |

## 3. 紀錄 `entries[]`

```json
{
  "id": "mg8k2x1a9f",
  "date": "2026-10-01",
  "time": "21:15",
  "title": "雨天的夜間散步",
  "body": "下班後雨剛停……",
  "mood": 3,
  "tags": ["散步", "思考"],
  "loc": "公園",
  "prompt": "今天有什麼小發現？",
  "fav": true,
  "edited": true,
  "photos": ["photos/mg8k2x1a9f-1.jpg", "photos/mg8k2x1a9f-2.jpg"]
}
```

有影片的紀錄：

```json
{
  "id": "mg8k3a7c2d",
  "date": "2026-10-02",
  "time": "08:05",
  "title": "",
  "body": "",
  "mood": 4,
  "tags": [],
  "loc": "",
  "video": {
    "id": "vmg8k3a7c9x1",
    "dur": 12.4,
    "type": "video/mp4",
    "file": "videos/vmg8k3a7c9x1.mp4",
    "poster": "photos/vmg8k3a7c9x1-poster.jpg"
  }
}
```

| 欄位 | 型別 | 必要 | 規則 |
|---|---|---|---|
| `id` | 字串 | ✅ | 1–40 個字元，只用 `A-Z a-z 0-9 _ -`。缺少或無效時，讀取端自己產生一個新的 |
| `date` | 字串 | ✅ | `YYYY-MM-DD`，**當地日期**，沒有時區。無效的紀錄整筆略過 |
| `time` | 字串 | | `HH:MM`（24 小時制）或空字串 |
| `title` | 字串 | | 去掉前後空白，最多 200 字 |
| `body` | 字串 | | 去掉前後空白，最多 50,000 字 |
| `mood` | 整數 | | 0–4：0 很低落、1 有點累、2 還可以、3 不錯、4 很棒。缺少或無效時用 2 |
| `tags` | 字串陣列 | | 每個去掉空白後最多 30 字，去重複，最多 20 個 |
| `loc` | 字串 | | 地點文字，最多 120 字 |
| `prompt` | 字串 | | 寫這則時用的「今日星語」題目，最多 200 字 |
| `fav` | 布林 | | 收藏（讀取時用真值判斷） |
| `edited` | 布林 | | 曾經編輯過 |
| `sample` | 布林 | | 第一次使用時放入的範例紀錄 |
| `photos` | 字串陣列 | | 照片路徑，最多 10 張，**第一張是封面** |
| `video` | 物件 | | 影片，見下表 |

**影片 `video`**

| 欄位 | 型別 | 規則 |
|---|---|---|
| `id` | 字串 | 符合 `^v[A-Za-z0-9_]{1,40}$`。影片在裝置上的儲存鍵，也用來判斷「這台裝置是否已經有這部影片」 |
| `dur` | 數字 | 長度（秒） |
| `type` | 字串 | MIME，例如 `video/mp4`、`video/quicktime` |
| `file` | 字串 | 影片檔路徑。影片檔已經不在裝置上時省略，此時還原後只有封面 |
| `poster` | 字串或 `null` | 封面圖片路徑 |

其他規則：

- 每則紀錄**照片和影片只能擇一**：有 `photos` 就沒有 `video`。
- `title`、`body`、照片、影片至少要有一項，否則整筆略過。
- 照片格式只能是 JPEG、PNG、WebP、GIF。網頁無法顯示 HEIC，iPhone 拍的照片要先轉成 JPEG 再寫入備份。
- 讀取時，照片單檔超過 20 MB 就略過。
- 看不懂的欄位一律保留或略過，**不要**報錯。

## 4. 個人資料 `profile`

所有欄位都是選填，讀取時只套用有出現而且有效的欄位。

| 欄位 | 型別 | 規則 |
|---|---|---|
| `avatar` | 字串 | 頭像代號，必須在 `data/avatars.json` 的清單裡；用照片頭像時是 `"photo"` |
| `photoAv` | 字串 | 照片頭像的路徑（`photos/avatar.jpg`）。網頁版限制約 450 KB |
| `name` | 字串 | 暱稱，最多 20 字 |
| `ship` | 字串 | 星艦名，最多 20 字 |
| `motto` | 字串 | 座右銘，最多 60 字 |
| `since` | 字串 | 開始使用的日期 `YYYY-MM-DD` |
| `birthday` | 字串 | `2000-MM-DD`。只用月日判斷星座，年份固定寫 2000 |
| `region` | 物件 | `{ "name": 字串(≤40), "lat": 緯度(-90–90), "lon": 經度(-180–180，選填) }` |
| `livery` | 整數 | 選用的階級塗裝，0–11 |
| `conOrder` | 字串陣列 | 星座點亮順序，值是 IAU 星座縮寫（見 `data/constellations.json`），例如 `["Ori","Del"]`。**要完整保留**，否則還原後已點亮的星座會變 |
| `nextPick` | 字串 | 使用者指定的下一個星座縮寫 |

## 5. 回顧紀錄 `reviews`

```json
{ "ids": { "mg8k2x1a9f": "2026-10-02" }, "last": "2026-10-02" }
```

- `ids`：重看過的舊紀錄 → 第一次重看的日期。每則會加回顧 XP。
- `last`：最後一次重看的日期。
- 還原時，只有在這台裝置**還沒有任何回顧紀錄**，而且使用者選擇還原個人資料時才套用。

## 6. 檔案清單 `files[]`

```json
[
  { "path": "photos/mg8k2x1a9f-1.jpg", "type": "image/jpeg", "size": 183204 },
  { "path": "videos/vmg8k3a7c9x1.mp4", "type": "video/mp4", "size": 18342011 }
]
```

- 列出 zip 裡每個照片和影片檔，各一次。
- 讀取端可以用它取得 MIME 類型、顯示進度，或檢查檔案是否缺少。
- `type` 缺少時，依副檔名判斷。

## 7. 還原（合併）規則

還原是**合併**，不會覆蓋或刪除裝置上已有的資料。

1. **判斷重複**：符合下列任一項，就當成已經存在並跳過：
   - `id` 和裝置上某則相同。
   - `date + time + title + body` 四項都和裝置上某則相同。
   - 同一份備份裡 `id` 重複的，只取第一筆。
2. **範例紀錄**：裝置上只有範例紀錄（`sample`），而備份裡有真正的紀錄時，先移除範例紀錄。
3. **個人資料**：由使用者勾選「同時還原個人資料」才套用。裝置上只有範例紀錄時，預設勾選。套用時只覆蓋備份裡有的欄位。
4. **開始日期**：如果匯入的紀錄裡最早的日期早於 `since`，把 `since` 改成那一天。
5. **影片**：zip 裡的影片，只有在裝置上還沒有同一個 `video.id` 時才寫入；重複的紀錄也照這個規則補回影片。
6. **預覽提示**：還原前要先告訴使用者：
   - 新紀錄幾則、已存在幾則、無法讀取幾則。
   - 有幾部影片會一起還原。
   - 有幾則紀錄的照片不在備份裡。
   - 有幾部影片「既不在備份裡，也不在這台裝置上」，還原後只會顯示封面。
7. **全部成功才寫入紀錄**：寫入失敗時（例如空間不足），回到還原前的狀態並提示使用者。

## 8. 不在備份裡的資料

| 資料 | 原因 |
|---|---|
| 密碼鎖 | 安全考量，換裝置後要重新設定 |
| 每日提醒和時間、減少動態效果、紅光夜視模式、清單顯示方式、時間格式（12／24 小時制） | 裝置設定，目前不備份 |
| 未完成的草稿 | 暫存資料 |
| 「新徽章」紅點、報告已讀、運勢延後提醒、最近的題目 | 暫時性的狀態 |
| 開發者工具的設定和測試標記 | 只供測試；測試紀錄會以一般紀錄的樣子匯出 |

等級、XP、連續天數、徽章、星座進度都是從紀錄、`reviews` 和 `conOrder` 算出來的，不需要另外備份。

## 9. 版本規則

- 欄位只增不改。新增欄位時版本號可以不變；舊的讀取端會略過看不懂的欄位。
- 改變既有欄位的意義或結構時，`v` 加 1，並在這份規格寫下舊版的讀法；讀取端要同時支援新舊版本。
- 讀到比自己新的版本時，仍然盡量讀取。可以提示「這份備份來自較新的版本，部分內容可能無法還原」，但不要直接拒絕。

## 10. Flutter 實作建議

| 用途 | 套件 |
|---|---|
| 讀寫 zip | [`archive`](https://pub.dev/packages/archive)（`ZipFileEncoder`／`ZipDecoder` 加 `InputFileStream`，大影片不必整個讀進記憶體） |
| 選備份檔 | [`file_picker`](https://pub.dev/packages/file_picker)（`allowedExtensions: ['zip','json']`） |
| 存出備份 | [`share_plus`](https://pub.dev/packages/share_plus)，讓使用者存到「檔案」、iCloud Drive、Google 雲端硬碟 |
| 暫存位置 | [`path_provider`](https://pub.dev/packages/path_provider)：先在暫存資料夾產生 zip，分享完再刪除 |

- **App 內部的儲存方式可以不一樣**（例如 SQLite 加上照片和影片檔案），只要匯出和匯入時照這份規格轉換即可。
- **`id` 沿用備份裡的值**，不要重新編號，否則重複判斷和回顧紀錄會對不上。新紀錄的 `id` 也照第 3 節的字元規則產生；影片 `id` 用 `v` 開頭。
- **日期**：`date` 是當地日期字串，不要轉成 UTC 時間戳記再轉回來，否則跨時區時日期會錯一天。
- **影片相容性**：iPhone 預設錄的是 HEVC（`.mov`），部分瀏覽器無法播放。想讓網頁版也能播放時，建議錄影時選擇「最相容」，或匯出前轉成 H.264 `.mp4`。
- **照片**：iPhone 的 HEIC 要轉成 JPEG 再寫入備份。網頁版把照片縮到長邊 1600 px、JPEG 品質 0.82，存在瀏覽器的 IndexedDB（和影片一樣，沒有 localStorage 的 5 MB 限制）。App 建議用相同設定，兩邊的備份大小和畫質才會一致。
- **測試**：用網頁版匯出一份含照片頭像、多張照片、影片、收藏、地區經度的備份，在 App 還原並逐項比對。再反過來測一次。
