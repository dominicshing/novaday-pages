# 優化紀錄

在 `claude/elegant-keller-yyl28m` 分支上持續檢查與優化 App。每一輪記錄找到的問題、修改內容，以及需要你決定的設計建議（這類不會自行修改）。

檢查方式：無頭 Chromium 走過所有頁面與面板（320px、390px、桌面），收集程式錯誤、超出畫面的元素、沒有名稱的按鈕、過小的點擊範圍，並檢視截圖；另外用「沒有紀錄」與「400 則長內容紀錄」兩種資料測試。

## 第 1 輪

**修正**
- 編輯個人資料的「星空頭像」：320px 寬的手機上一排 6 個放不下，最右邊一欄被裁掉。改成空間夠時一排 6 個，窄螢幕自動減為 5 個，每個至少 44px。
- 星光月曆：320px 寬時，日期格只有約 35px，月相與星座標記會壓到兩位數日期（例如 10、24）。窄螢幕時標記縮小並貼齊左上角。

**檢查結果良好**
- 所有頁面與面板在 320px、390px 都沒有程式錯誤、沒有左右捲動。
- 沒有紀錄、400 則紀錄時也沒有錯誤。

## 第 2 輪：效能

用 1000 則紀錄測量各畫面的繪製時間（390px，無頭 Chromium）。

**修正**
- 「我的」頁的階級輪播：每次重繪（例如存一則日記）都會整排重建 28 張卡片（徽章、星空背景），約 300ms。改成只有階級或星線顏色改變時才重建，平常只更新進度列。
- CSS 的 `:has()` 選擇器讓頁面上任何一點變動都要重新計算全部 12000 多個元素的樣式（每次約 90ms）。改用一般 class：
  - 減少動態效果：`#device:has(.app.calm)` → `#device.calm`（切換時同步加在 `#device` 上）。
  - 有縮圖的日記卡片：`.entry:has(.thumb-w)` → `.entry.th`；沒有內文的卡片加 `.nb`。
  - 連續天數為 0 時的火焰：`.fuel:has(.flame-ic.off)` → `.fuel.off`。

| 1000 則紀錄 | 修改前 | 修改後 |
|---|---|---|
| 重繪「我的」頁 | 473ms | 44ms |
| 開啟日記詳情 | 28ms | 10ms |
| 開啟編輯器 | 66ms | 51ms |
| 一次小變動的樣式計算 | 約 98ms | 約 14ms |
