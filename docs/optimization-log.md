# 優化紀錄

在 `claude/elegant-keller-yyl28m` 分支上持續檢查與優化 App。每一輪記錄找到的問題、修改內容，以及需要你決定的設計建議（這類不會自行修改）。

檢查方式：無頭 Chromium 走過所有頁面與面板（320px、390px、桌面），收集程式錯誤、超出畫面的元素、沒有名稱的按鈕、過小的點擊範圍，並檢視截圖；另外用「沒有紀錄」與「400 則長內容紀錄」兩種資料測試。

## 第 1 輪

**修正**
- 編輯個人資料的「星空頭像」：320px 寬的手機上一排 6 個放不下，最右邊一欄被裁掉。改成空間夠時一排 6 個，窄螢幕自動減為 5 個，每個至少 44px。
- 星光月曆：320px 寬時，日期格只有約 35px，月相與星座標記會壓到兩位數日期（例如 10、24）。窄螢幕時標記縮小並貼齊左上角。

**檢查結果良好**
- 所有頁面與面板在 320px、390px 都沒有程式錯誤、沒有左右捲動。
- 沒有紀錄、400 則紀錄時也沒有錯誤。

## 第 2 輪：效能

用 1000 則紀錄測量各畫面的繪製時間（390px，無頭 Chromium）。

**修正**
- 「我的」頁的階級輪播：每次重繪（例如存一則日記）都會整排重建 28 張卡片（徽章、星空背景），約 300ms。改成只有階級或星線顏色改變時才重建，平常只更新進度列。
- CSS 的 `:has()` 選擇器讓頁面上任何一點變動都要重新計算全部 12000 多個元素的樣式（每次約 90ms）。改用一般 class：
  - 減少動態效果：`#device:has(.app.calm)` → `#device.calm`（切換時同步加在 `#device` 上）。
  - 有縮圖的日記卡片：`.entry:has(.thumb-w)` → `.entry.th`；沒有內文的卡片加 `.nb`。
  - 連續天數為 0 時的火焰：`.fuel:has(.flame-ic.off)` → `.fuel.off`。

| 1000 則紀錄 | 修改前 | 修改後 |
|---|---|---|
| 重繪「我的」頁 | 473ms | 44ms |
| 開啟日記詳情 | 28ms | 10ms |
| 開啟編輯器 | 66ms | 51ms |
| 一次小變動的樣式計算 | 約 98ms | 約 14ms |

## 第 3 輪：XP 計算快取

圖鑑頁每張星座卡（88 張）都要知道目前的星線顏色，每次都從頭計算全部紀錄的 XP。

**修正**
- `xpMap` 依紀錄內容快取：只要影響 XP 的欄位（id、日期、時間、照片／影片、地點、今日星語）沒變，就直接用上次的結果；保留最近兩份，因為編輯器會輪流計算「目前紀錄」和「加上草稿」。
- `reviewXP` 原本對每個回顧過的 id 掃描全部紀錄，改成先建 Set。

| 3000 則紀錄 | 修改前 | 修改後 |
|---|---|---|
| 開啟圖鑑 | 426ms | 56ms |
| 開啟編輯器 | 228ms | 84ms |

## 第 4 輪：壞資料不再讓 App 打不開

用各種格式錯誤的資料測試（心情是 7、標籤不是陣列、日期 2026-13-45、紀錄是 null、整份資料不是陣列、個人資料欄位型別錯誤）。修改前，這些情況都會在啟動時出錯，畫面一片空白；而且整份資料無法解析時，下一次存檔會蓋掉原始資料。

**修正**
- 讀取紀錄時逐筆修正：心情、時間、標籤、文字欄位改回正確格式，重複的 id 換新；不存在的欄位維持不存在（舊紀錄不受影響）。
- 修不好的（不是物件、沒有正確日期）不載入，但**不刪除**：只要有任何修改，原始資料整份存到 `orbitlog.entries.broken.v1` 留底。
- 個人資料：暱稱、生日、地區、星線顏色、星座順序、提醒時間等欄位型別錯誤時改回預設值（規則和匯入備份時相同）。
- 匯入備份本來就有完整檢查，這次確認沒有問題。
- XSS 測試：在標題、內文、標籤、地點、暱稱、座右銘、地區放入 HTML，走過所有畫面，沒有任何內容被當成 HTML 執行。
- 新增 `tests/storage.test.mjs`（9 項）。

## 第 5 輪：鍵盤與螢幕報讀

**修正**
- 面板打開時，焦點原本留在後面被蓋住的頁面；按 Tab 會跑到看不見的按鈕上。現在打開面板時焦點移進面板（呼叫端自己指定焦點的，例如確認對話框，維持原樣），Tab／Shift+Tab 只在最上層的面板裡循環。
- 關閉日記詳情時，日記列表常已經重畫，原本的按鈕不存在，焦點掉到頁面最上面。現在會找到重畫後的同一則紀錄。
- 新增 `tests/a11y.test.mjs`（7 項）。

## 第 6 輪：日期正確性、橫向手機

**檢查結果良好**
- 在紐約（夏令時間切換）、查塔姆群島（+12:45）、聖誕島（+14）、紐芬蘭（-3:30）四個時區執行全部測試，全部通過。
- 連續天數、XP、觀星第幾天、月曆：跨夏令時間開始與結束、跨年、2028 年 2 月 29 日都正確。
- 反覆開關畫面 60 次：元素數量與記憶體穩定，沒有洩漏。

**修正**
- 手機橫拿（例如 844×390）時，寬度超過 600px 會被當成電腦，畫面變成一支縮得很小的手機模型。現在電腦預覽外框要「寬 ≥ 600px 而且高 ≥ 600px」才顯示，手機橫拿直接用全螢幕版面。CSS 與 JS 共用同一個條件（`FRAME_MQ`）。
- 修正程式註解：連續天數的「每週」是週日到週六（和月曆一致），不是週一到週日。

**建議（未修改）**
- 手機橫拿時，編輯器底部的心情列佔掉大半高度，寫字區要往上捲才看得到。如果你希望支援橫向書寫，可以在矮螢幕時把心情列縮成一排小圖示。

## 第 7 輪：清除不再使用的程式碼

**移除**
- 沒有任何地方呼叫的函式：`openMonth`（舊的「本月紀錄」面板入口，面板本身仍供月報使用）、`setPhoto`、`starPath`、`xpOf`、`conVis`、`phIsSrc`、月曆裡的 `_unused`、徽章水晶的 `CR_FACETS`、`CR_TABLE`。
- CSS 裡已經沒有對應元素的選擇器：`.beacon`、`.engine`、`.fresh-ring`、`.sky-c`、`.cfig`、`.ob-first`、`.detail .actions`（多半是太空主題時期的遺留）。
- 掃描時被誤判為未使用、實際上由程式組出名稱的 class（例如 `nv0`～`nv4`、頭像動畫 `v*`、`is-done`）都保留。

## 第 8 輪：用真的點擊走一遍使用流程

新增 `tests/journey.test.mjs`（12 項），用點擊與輸入完成：寫一則（心情、地點、標籤）→ 打開詳情 → 編輯標題 → 搜尋 → 刪除 → 復原。

**找到並修正的問題**
- 在「標籤」或「地點」欄位按 Enter（手機鍵盤的「完成／前往」鍵）會**直接點亮送出**，還沒寫內文就存檔了。標題欄位也一樣。現在：
  - 標題按 Enter 跳到內文。
  - 地點、標籤按 Enter 收起鍵盤。
  - 手機鍵盤的按鍵文字改成「下一步」（標題）與「完成」（地點、標籤）。
  - 想直接點亮仍可按 Ctrl／⌘+Enter；中文輸入法選字時的 Enter 不受影響。

## 第 9 輪：中文輸入法

注音、拼音輸入法選字時按的 Enter／Esc 也會觸發鍵盤事件（`isComposing`）。原本有 4 個欄位沒有排除：

| 欄位 | 選字時按 Enter 原本會 |
|---|---|
| 日記搜尋 | 收起鍵盤，打斷輸入 |
| 引導頁的暱稱 | 收起鍵盤 |
| 編輯個人資料的暱稱 | 跳到座右銘欄位 |
| 標籤管理的改名 | **直接儲存打到一半的標籤名稱** |

另外，選字時按 Esc（取消選字）會把整個面板關掉。

**修正**：新增共用的 `isEnter(e)`（排除選字中的 Enter），上面 4 個欄位與編輯器都改用它；選字中的 Esc 不再關閉面板。測試加 2 項。

## 第 10 輪：密碼鎖

**找到並修正的問題**
- **「忘記密碼？」沒有反應**：確認對話框其實開在密碼鎖的**後面**（z-index 26 < 70），使用者看不到，等於無法重設。現在密碼鎖開著時，面板會疊在鎖上面。
- **上鎖時日記內容仍可被讀取**：鎖後面的畫面還能用 Tab 移過去，螢幕報讀也讀得到日記。現在上鎖時，鎖以外的畫面都設為 `inert`。
- 「忘記密碼？」重設原本只清 localStorage，照片與影片留在 IndexedDB（下次開啟才被清理）。現在一起立即清除。
- 確認對話框開著時，鍵盤數字不再輸入密碼。
- 照片清理（`mediaGC`）會保留第 4 輪留底資料（`orbitlog.entries.broken.v1`）裡用到的照片，避免留底的紀錄失去照片。
- 新增 `tests/lock.test.mjs`（7 項）。

## 第 11 輪：引導頁（320×568）

用點擊走完整個引導流程（320×568，iPhone SE 第一代大小），沒有錯誤。

**修正**
- 最後一頁「準備好了」：星座圖佔掉大半高度，說明的最後一句「不用寫很多，一句話也可以。」被按鈕蓋住。矮螢幕（高度 ≤ 620px）時星座圖從 300px 縮成 220px，說明完整顯示。

## 第 12 輪：分享圖卡

用特殊符號（`& < > " '`）、emoji、超長標題與內文、沒有空格的長字串、控制字元測試日記與星座的分享圖卡。

**檢查結果良好**：符號都有正確跳脫，長文字會換行並以「…」截斷。

**修正**
- 從其他 App 貼上的文字可能夾帶控制字元（例如 `\u000b`），或落單的 emoji 半個字元。原本會讓整張圖卡「產生失敗」，甚至丟出錯誤。現在 SVG 轉圖片時統一經過 `svgURL()`，去掉 XML 不允許的字元。日記卡片背景的星座圖也改用它。
- 新增 `tests/share.test.mjs`（3 項）。

## 第 13 輪：大量資料下的報告與圖鑑

用 400 則紀錄（含生日、地區）在 320px 檢視月報、年度回顧、星座運勢、星座詳情、「我的」、圖鑑、首頁，版面都正常。

**修正**
- 年度回顧在「今年 276 天寫了 275 天」時顯示 **100%**（99.6% 四捨五入）。新增 `pctDone()`：還沒全部完成時最多顯示 99%，有進度時至少 1%。月報、年度回顧、等級經驗值的百分比都改用它。
